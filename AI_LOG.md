\# AI\_LOG.md — AI Tech Consultant Capstone



\## 1. Useful AI Prompts



\*\*Prompt 1 — Project Architecture\*\*



Help me build an AI Tech Consultant capstone with three independent agents: a Knowledge Brain in Python, an Inbox Agent in TypeScript, and a Meeting-to-Scope Agent in Python. Explain the folder structure and responsibilities of each agent.



\*\*Prompt 2 — Knowledge Brain\*\*



Help me implement a FastAPI Knowledge Brain with knowledge retrieval, cited answers, an abstention mechanism when information is insufficient, and feedback endpoints. Explain each code block simply.



\*\*Prompt 3 — Inbox Agent\*\*



Help me implement a TypeScript email agent that categorizes customer emails, drafts replies, supports human editing and approval, and prevents emails from being sent without authorization.



\*\*Prompt 4 — Meeting-to-Scope Agent\*\*



Help me build a Python API that extracts requirements from meeting transcripts, estimates effort, identifies scope changes between meetings, and creates proposals that require human approval.



\*\*Prompt 5 — Testing and Evaluation\*\*



Help me test all three agents, identify failures, create realistic test cases, measure accuracy, and document limitations. Provide commands I can run locally to verify the results.



\## 2. AI Answer Rejected or Modified



I did not treat successful tests or generated code as proof that every requirement was complete. I retained fallback behavior when the Claude API was unavailable and documented that live Claude integration had not been verified. I also kept human approval as a safeguard for sensitive actions rather than claiming that the agents could safely perform them automatically.



\## 3. Reflection



AI assistance helped me understand the project structure, implement API endpoints, debug errors, and write tests. I learned that generated code must be reviewed and tested, and that limitations should be documented honestly rather than presenting unverified functionality as complete.
